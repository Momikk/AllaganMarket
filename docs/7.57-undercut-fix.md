# 国服 7.57 压价高亮修复

发布版本：1.4.0.3，API 15。以原版实际发布版本 1.4.0.2 为基线，保留 Momikk 作者与中文安装器元数据。

## 故障依据

本机 2026-10-13 21:20:25 的 Dalamud 日志明确记录：InventoryService 的 containerInfoNetworkHook 无法匹配 Text signature。该 Hook 无法启用后，loadedInventories 无法记录雇员市场库存，RetainerMarketService 的 HasSeenInventory 检查会拦截数据读取和修改事件，销售快照可能保留旧价格。

原版提交 2242b07cec028ffa3454bfc7b255d85ce9cb5b7e（4.0.2 / Update sig for 7.55）将处理函数入口签名替换成较长的 E8 调用点签名。该调用点签名在本机游戏文件 .text 中匹配 0 次，原处理函数入口签名匹配 1 次，RVA 为 0xB4A390。因此本 fork 恢复原处理函数入口签名，不更改 Hook 委托或封包偏移。

检查对象：ffxivgame.ver 为 2026.10.06.0000.0000；ffxiv_dx11.exe SHA256 为 958b78e278ad896493c484eb313ff605ab41edefef74f92b0ee078e69b281bf9。scripts/check-signatures.py 可重做检查，并断言当前发布签名在 .text 中唯一匹配。此验证针对当前国服文件，不代表其他区服也使用相同入口。

另外，RetainerListDraw 原逻辑仅设置红色或黄色，压价和待更新状态同时解除时没有恢复分支，红色与附加的压价数量可一直残留。修复后正常状态恢复原始文本与颜色，从红色变为待更新黄色时也恢复原始文本。

## 验证

签名匹配回归检查通过；Release 构建成功，0 错误、130 警告；安装包 manifest 与 DLL 版本同为 1.4.0.3，API 15。未执行实际游戏内 Hook 与交互测试，不能将静态唯一匹配等同于运行验收。

更新后先关闭并重新打开雇员窗口，使库存包重新到达。检查加载日志不再出现 containerInfoNetworkHook 签名失败；选择被压价物品并修改售价，确认插件显示的新售价与游戏一致；价格已具备竞争力且市场缓存未过期时应恢复普通颜色。黄色表示市场缓存需要刷新，与红色压价状态不同。最后验证切换雇员、销售列表关闭重开和插件禁用重载。
